Native Federation evaluation

Three separately built and separately deployed Angular applications, composed in the browser at runtime. This page exists to answer three questions, not to look like a product.

1. Can a remote be deployed on its own?

Rebuild and redeploy one remote, reload this page, and check the evidence table at the bottom. Only that app's build id changes. The shell is never rebuilt because remote URLs are read from federation.manifest.json at runtime, not compiled in.

2. Can the teams move independently?

Each app has its own package.json, its own lockfile and its own node_modules. The evidence table shows the Angular version each one was built against, so a deliberate version skew becomes visible instead of silent.

3. Is this safe for production?

Stop a remote's server and open its route: the shell keeps working and only that section shows a failure. Shared session and cart state live in one @mfe-demo/platform instance; the evidence table reports if that instance was ever duplicated.
